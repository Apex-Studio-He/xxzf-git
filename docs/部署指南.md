# XXZF 小白部署指南

如果你从没搭过服务器，先别被后面的命令吓到。整件事只有三段：

```text
第一段：让你配置的 HTTPS /xxzf 地址能打开
第二段：把同一个地址写进 Android / Mac / Windows 客户端
第三段：用六位码配对，发一条测试通知
```

本文使用 `https://notify.example.com/xxzf` 和 `https://updates.example.com/downloads/forwarder/test` 作为填写示例。它们不能用，照做时把 `notify.example.com` / `updates.example.com` 换成你自己的域名。

## 开始前先打勾

- [ ] 我有一台能长期运行的 macOS 或 Linux 设备。
- [ ] 我有一个域名，而且能修改它的 DNS。
- [ ] 我能给这个域名配置 HTTPS 证书。
- [ ] 我能登录服务器并使用管理员权限安装 Nginx。
- [ ] 我知道真实密码、私钥、Bark Key 只保存在自己的电脑/服务器，不发到聊天或 Git。

有任意一项不确定，可以先走 [Codex 小白构建流程](../CODEX.md)；它会先检查环境，不会一上来就改服务器。

## 文中几个词是什么意思？

- **域名**：类似 `notify.example.com` 的网站名字。
- **DNS**：告诉互联网“这个域名对应哪台服务器”。
- **HTTPS / TLS 证书**：让客户端确认连到的是你的服务器，中间人不能偷改数据。
- **Nginx**：守在公网门口，只把 XXZF 允许的请求交给 Python 服务。
- **回环地址 `127.0.0.1`**：只有服务器自己能访问，外网无法绕过 Nginx 直接连 Python。

每做完一节，先看该节最后的检查命令是否通过，再继续下一节。

## 1. 准备服务器与域名

推荐使用独立的非 root 用户 `xxzf`：

```bash
sudo useradd --system --home /var/lib/xxzf --shell /usr/sbin/nologin xxzf
sudo install -d -m 0755 -o root -g root /opt/xxzf
sudo install -d -m 0700 -o xxzf -g xxzf /var/lib/xxzf
sudo install -d -m 0750 -o root -g xxzf /etc/xxzf
```

macOS 不需要创建系统用户，但同样要把数据目录放在源码树外，并设为 `0700`。

DNS 的 A/AAAA 记录指向服务器。通过 Let's Encrypt、云厂商或其他可信 CA 获取证书。Android、macOS 和 Windows 客户端都拒绝明文 HTTP；不要通过关闭 TLS 校验来排障。

## 2. 安装源码与静态页

```bash
sudo rsync -a --delete --exclude .git ./ /opt/xxzf/
sudo install -d -m 0755 /opt/xxzf/public/bark
```

`public/bark/` 已随第一条命令安装；第二条只确保权限和目录存在。运行数据、日志、密钥和安装包不要放在 Git 工作树中。

## 3. 生成服务端兼容令牌

```bash
sudo -u xxzf /opt/xxzf/scripts/provision_notify_token.sh \
  /var/lib/xxzf/notify-token.txt
sudo stat -c '%a %U %G %n' /var/lib/xxzf /var/lib/xxzf/notify-token.txt
```

期望目录为 `700`、令牌为 `600`。脚本不会把令牌打印到终端；已有合格令牌不会被覆盖。

## 4. 配置环境

复制示例，而不是直接编辑仓库中的文件：

```bash
sudo cp /opt/xxzf/.env.example /etc/xxzf/xxzf.env
sudo chown root:xxzf /etc/xxzf/xxzf.env
sudo chmod 0640 /etc/xxzf/xxzf.env
sudoedit /etc/xxzf/xxzf.env
```

至少修改：

```dotenv
DATA_DIR=/var/lib/xxzf
XXZF_TOKEN_FILE=/var/lib/xxzf/notify-token.txt
XXZF_AUDIT_DIR=/var/lib/xxzf/notification_archive
XXZF_DIAGNOSTIC_DIR=/var/lib/xxzf/diagnostics
XXZF_BARK_SECRET_FILE=/var/lib/xxzf/bark-secrets.json
XXZF_BARK_ICON_DIR=/var/lib/xxzf/bark-icons
XXZF_PUBLIC_BASE=https://notify.example.com/xxzf
XXZF_PUBLIC_ORIGIN=https://notify.example.com
XXZF_BARK_BIND_PAGE=https://notify.example.com/xxzf/bark/
XXZF_BARK_ALLOWED_BASES=https://api.day.app
```

`HOST` 必须保持数字回环地址 `127.0.0.1`。服务端会主动拒绝 `0.0.0.0`，公网只应通过 Nginx 的精确路由进入。

## 5. 启动服务

### Linux / systemd

```bash
sudo cp /opt/xxzf/deploy/systemd/xxzf.service.example \
  /etc/systemd/system/xxzf.service
sudo systemctl daemon-reload
sudo systemctl enable --now xxzf
sudo systemctl status xxzf --no-pager
curl --fail http://127.0.0.1:8787/api/v1/health
```

### macOS / launchd

复制 `deploy/launchd/com.zundu.xxzf.server.plist.example` 到 `~/Library/LaunchAgents/`，把每个 `/ABSOLUTE/...` 换成真实绝对路径，把示例域名换成自己的域名，然后：

```bash
plutil -lint ~/Library/LaunchAgents/com.zundu.xxzf.server.plist
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.zundu.xxzf.server.plist
launchctl kickstart -k gui/$(id -u)/com.zundu.xxzf.server
curl --fail http://127.0.0.1:8787/api/v1/health
```

不要直接安装 `.example` 文件；带占位符的配置故意不能工作。

## 6. 配置 Nginx 与 HTTPS

1. 将 `deploy/nginx/xxzf-server.conf.example` 合并到 Nginx `http {}` 与目标 `server {}`。
2. 将 `nginx/xxzf_public_routes.inc` 复制到 `/etc/nginx/xxzf_public_routes.inc`。
3. 将路由文件中的 `/opt/xxzf/public` 改为你的静态目录（如果不同）。
4. 更新路由中的精确安装包文件名，仅保留你实际发布的版本。
5. 检查并重载：

```bash
sudo nginx -t
sudo systemctl reload nginx
curl --fail https://notify.example.com/xxzf/v1/health
```

父级 Nginx 配置必须定义 `zundu_api_per_ip` 和 `zundu_conn_per_ip` 两个 zone。路由 include 最后用 `location ^~ /xxzf/ { return 404; }` 拒绝未列出的路径；不要用宽泛反向代理替代。

审计页和管理 API 应只允许在服务器本机访问，不要为它们配置公网路由。

## 7. 替换客户端服务地址

三个客户端会在构建时固定服务地址，这是防止配置被劫持的安全设计。将 `https://example.com/xxzf` 替换为你的 `XXZF_PUBLIC_BASE`：

- Android：`android/src/com/zundu/notifybridge/ServerPolicy.java`
- macOS 核心：`server/mac_client.py`
- macOS UI：`server/mac_receiver/Receiver.m`
- macOS 启动脚本：`scripts/start_air_notifier.sh`
- Windows：`windows/Forwarder.cs`

替换后同时更新相应测试中的期望值，再运行全套测试。地址必须是 HTTPS、无用户名密码、无 query/fragment，路径大小写要完全一致。

## 8. 配置安全更新

仓库内置的是无法用于发布的示例公钥，私钥从未保留。部署者必须生成自己的 3072 位 RSA 密钥：

```bash
/opt/xxzf/scripts/generate_update_key.sh \
  /绝对/仓库外/私密路径/xxzf-update-signing
```

脚本生成：

- `update-private.pem`：发布私钥，`0600`，只留在离线或受控发布机。
- `update-public.pem` / `update-public.der`：公钥。
- `update-public-values.txt`：Key ID、DER Base64、Windows modulus。

将新值同步到以下文件：

- `android/.../UpdateSecurity.java`
- `server/mac_receiver/UpdateManager.m`
- `windows/Updater.cs`
- `scripts/publish_test_update.py`
- `scripts/verify_published_update.py`

再将 `https://updates.example.com/downloads/forwarder/test`、host 和 path prefix 替换成自己的更新 HTTPS 地址，并更新测试。所有客户端、公用验证器与发布器的 Key ID、公钥、域名和路径必须完全一致。

发布示例：

```bash
export XXZF_UPDATE_PRIVATE_KEY=/绝对/私密路径/xxzf-update-signing/update-private.pem
python3 scripts/publish_test_update.py \
  --platform android \
  --version-code 27 \
  --version 0.9.17 \
  --notes '安全与稳定性修复' \
  --package dist/NotifyBridge-release.apk \
  --output-root /tmp/xxzf-update
python3 scripts/verify_published_update.py \
  /tmp/xxzf-update/android.json --package-root /tmp/xxzf-update
```

## 9. 构建客户端

### Android

```bash
./scripts/install_android_tools.sh
./android/test_receiver.sh
./android/test_security.sh
./android/build.sh
```

客户发布必须设置 `BUILD_VARIANT=release` 以及[配置参考](配置参考.md)中的 release keystore 变量。

### macOS

```bash
xcode-select --install
./server/mac_receiver/build.sh
./server/mac_receiver/package.sh
```

给他人分发时配置 Developer ID，签名后再运行 `scripts/notarize_macos_release.sh`。

### Windows

在 Windows PowerShell：

```powershell
.\windows\build.ps1
.\windows\build-installer.ps1
```

Release 版本必须用 Authenticode 证书签名。

## 10. Bark 与验收

1. iPhone 安装 Bark，允许通知。
2. Android 授予通知读取、后台运行权限，只勾选需要转发的 App。
3. Android 进入 Bark 绑定，iPhone 打开二维码中的自建页面。
4. 粘贴 Bark 测试 URL，完成一次性绑定。
5. 验收通知显示 `安卓-应用名`、来源 App 图标与标题，但不包含正文。图标需要 `XXZF_PUBLIC_BASE` 可由 Bark 通过公网 HTTPS 访问，并保留 Nginx 的 `/xxzf/v1/bark/icons/` 精确路由。
6. 验收 Android 熄屏、Wi-Fi/蜂窝切换、服务器重启、接收端断线重连、单独删除设备。

如使用自建 Bark Server，把它的完整 HTTPS base（可带路径前缀）写入 `XXZF_BARK_ALLOWED_BASES`，并在 Bark App 中添加同一个服务器。白名单必须是精确地址，不支持通配符。

## 11. 上线前检查

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s server -p 'test_*.py'
./android/test_receiver.sh
./android/test_security.sh
./server/mac_receiver/test_update_manager.sh
./scripts/privacy_scan.sh
```

最后从干净 checkout 构建并确认 Git 中没有 `.env`、数据库、日志、通知归档、安装包、证书或私钥。
