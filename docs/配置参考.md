# 配置参考

## 服务端环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `HOST` | `127.0.0.1` | 必须是数字回环地址；非回环会拒绝启动 |
| `PORT` | `8787` | Python 服务监听端口 |
| `DATA_DIR` | macOS 用户 Application Support 下的 `XXZF/server-data` | 数据库和私密配置根目录；生产建议显式设置 |
| `XXZF_TOKEN_FILE` | `$DATA_DIR/notify-token.txt` | 旧 API 兼容 Bearer token，必须是私密普通文件 |
| `XXZF_AUDIT_DIR` | `$DATA_DIR/notification_archive` | 有界通知归档目录 |
| `XXZF_DIAGNOSTIC_DIR` | `$DATA_DIR/diagnostics` | 有界诊断目录 |
| `XXZF_BARK_SECRET_FILE` | `$DATA_DIR/bark-secrets.json` | Bark device key 的 `0600` 私密文件 |
| `XXZF_APK_FILE` | `dist/NotifyBridge-release.apk` | 本地管理页提供的 APK；不存在时不会自动下载其他地址 |
| `XXZF_PUBLIC_BASE` | `https://example.com/xxzf` | 客户端公网 API base |
| `XXZF_PUBLIC_ORIGIN` | `https://example.com:8443` | 允许的 HTTPS origin/Host 依据 |
| `XXZF_BARK_BIND_PAGE` | `https://example.com/xxzf/bark/` | 一次性 Bark 绑定页 |
| `XXZF_BARK_ALLOWED_ORIGINS` | `https://api.day.app` | 逗号分隔的 Bark HTTPS origin 白名单 |
| `XXZF_AUDIT_MAX_BYTES` | 代码内默认值 | 通知归档上限 |
| `XXZF_DIAGNOSTIC_MAX_BYTES` | 代码内默认值 | 诊断数据上限 |

不要把 token 或 Bark Key 放进 URL、命令行参数、Nginx access log、GitHub Actions secret 以外的 workflow 文本或公开 issue。

## 客户端固定地址

业务 API base 位于：

- Android `ServerPolicy.java`
- macOS `mac_client.py`、`Receiver.m`
- Windows `Forwarder.cs`

更新 base、host、path prefix 位于：

- Android `UpdateSecurity.java`
- macOS `UpdateManager.m`
- Windows `Updater.cs`
- 发布器 `scripts/publish_test_update.py`
- 独立验证器 `scripts/verify_published_update.py`

生产构建必须保持这些值一致。固定地址是防止客户端被运行时配置劫持的安全边界，不提供任意 URL 输入框。

## Android 构建

通用变量：`JAVA_HOME`、`ANDROID_HOME`、`ANDROID_API`、`BUILD_TOOLS_VERSION`、`BUILD_VARIANT=debug|release`。

Release 必填：

- `XXZF_ANDROID_KEYSTORE`
- `XXZF_ANDROID_KEY_ALIAS`
- `XXZF_ANDROID_STORE_PASS_FILE`
- `XXZF_ANDROID_KEY_PASS_FILE`
- `XXZF_ANDROID_EXPECTED_CERT_SHA256`

keystore 和两个密码文件必须是非符号链接的私密普通文件，且 group/other 无权限。密码通过文件传给 `apksigner`，不要写进脚本或 CI 日志。

## macOS 发布

`BUILD_VARIANT=release` 时必填：

- `XXZF_MAC_SIGN_IDENTITY`：必须以 `Developer ID Application: ` 开头。
- `XXZF_MAC_EXPECTED_TEAM_ID`：用于签后身份固定。
- `XXZF_NOTARY_KEYCHAIN_PROFILE`：仅公证脚本使用，由 `notarytool store-credentials` 预先保存。

Debug 使用 ad-hoc 签名，只适合本机测试。

## Windows 发布

设置 `XXZF_BUILD_VARIANT=Release`，并配置：

- `XXZF_WINDOWS_SIGN_CERT_SHA256`：代码签名证书 DER 的 SHA-256。
- `XXZF_SIGNTOOL`：`signtool.exe` 不在 PATH 时指定绝对路径。

脚本要求恰好一个带私钥的证书匹配固定摘要，使用 SHA-256 和 DigiCert RFC 3161 时间戳，然后再次验证签名。

## 更新发布

- `XXZF_UPDATE_PRIVATE_KEY`：仓库外 `0600` RSA 私钥。
- `XXZF_UPDATE_SSH_TARGET`：显式远程目标；没有设置时部署脚本拒绝联网。
- `XXZF_UPDATE_REMOTE_ROOT`：远端静态文件目录，默认 `/opt/xxzf/public/downloads/forwarder/test`。

清单签名覆盖 schema、channel、platform、versionCode、version、URL、SHA-256、size、发布时间、notes 和 Key ID。客户端会拒绝额外字段、错误 host/path、重定向、过大文件、摘要或签名不符。

## 真机链路测试

- `XXZF_MINI_SSH_TARGET`：显式指定自己的测试服务器；缺失时脚本拒绝执行。
- `XXZF_MAC_RECEIVER_LOG`：macOS 接收日志路径。
- `XXZF_EXPECTED_ANDROID_VERSION` / `XXZF_EXPECTED_ANDROID_CODE`：真机预期版本。

真机脚本只用于已授权设备。不要把设备序列号、通知正文、配对密钥或服务器登录信息粘贴到公开 issue。
